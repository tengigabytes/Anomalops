# :core:gpu

多幀運算的 GPU 版（ADR-0017）：OpenGL ES 3.1 運算著色器，從 Kotlin 呼叫，不用 NDK。CPU 參考版在 `:core:imaging`，每支著色器都和對應的 CPU 函式比對。

| 項目 | 內容 |
| --- | --- |
| 職責 | 在 GPU 上做 FR-17 低光合成與 FR-33 景深合成的對齊、合成與輸出；目前在第 4 步（FR-17 從 RAW 到 ARGB 已完成，與 CPU 相同）；第 5 步 FR-33 候選 A、B 與 `StackGuard` 完成 |
| 依賴 | `:core:imaging`（共用 `Plane`、`Similarity`、`Region` 與 CPU 參考函式） |
| 被誰使用 | 尚未接上；之後由 `:app` 使用 |
| 對應需求 | FR-17、FR-33（ADR-0015、ADR-0017） |
| 內容 | `GlesContext`（無畫面的 EGL 環境，建立它的執行緒才能用）、`ComputeProgram`（編譯、uniform、dispatch）、`GpuPlane` 與 `PlaneFormat`（`FLOAT32` 為 R32F；`HALF` 暫存在 RGBA16F 的紅色通道，因為 R16F 不能當寫入目標）、`PlaneTransfer`（上傳先進 32 位元紋理、在 GPU 上轉半精度；下載經儲存緩衝）、`PlaneKernels`（`half` 對應 `Plane.half`、`warp` 對應 `FrameAligner.warp`、`warpFiltered` 改用硬體雙線性；可用 `into` 寫進重複使用的輸出平面，每次新配置紋理很慢）、`MeanSquaredDiffKernel`（一次算一批候選變換的 `meanSquaredDiff`；每個執行緒走 8 列、每個工作群組在共享記憶體加總，CPU 以 double 合計，見 [m9-gpu-fr17.md](../../docs/test/m9-gpu-fr17.md)）、`GaussNewtonKernel`（高斯牛頓一輪的法方程式，對應 `GradientSums`；加總方式同上）、`GpuPyramid`（與 `Pyramid` 相同的層數；`rebuild` 把下一張的金字塔寫進同一組平面）、`GpuGlobalAligner`（整張對齊：搜尋與高斯牛頓的迭代直接用 `GlobalAligner`、`GaussNewton` 的程式，只有代價與法方程式在 GPU 上算）、`GpuTileAligner`（逐塊對齊，對應 `TileAligner`；一個工作群組跑完一塊的整個搜尋，著色器在 `TileShaders`；參考張的紋理量與可信門檻每張參考張算一次）、`GpuLowLightMerge`（FR-17 合成，對應 `LowLightMerge`，逐張對齊並累加到 GPU 上的平面，最多 3 個色版；著色器在 `MergeShaders`）、`GpuDevelop`（FR-17 的兩端：RAW 以 R16UI 紋理上傳，解成半尺寸的 R、G、B 與亮度，對應 `Demosaic.halfSize` 與 `Rgb.luma`，線性值查 CPU 做好的表；合成後的相機 RGB 轉成 8 位元 sRGB ARGB，對應 `Render.toArgb`，sRGB 查表以相同算式產生；`RenderOptions.sharpen` 大於 0 時再跑一支整數運算的銳化著色器，對應 `Sharpen.apply`；著色器在 `DevelopShaders`）、`GpuFocusAccumulator`（逐張加入的景深合成介面，對應 `FocusAccumulator`）、`GpuContrastSelect`（FR-33 候選 A，兩輪）與 `GpuLaplacianPyramid`（候選 B），共用 `StackKernels`、`StackShaders`（盒狀平均以 float 加總，CPU 是 double；見 [m9-gpu-fr33.md](../../docs/test/m9-gpu-fr33.md)）、`GpuStackGuard`（對應 `StackGuard`：補缺的像素、合成不比最清晰的單張清楚就退回；著色器在 `GuardShaders`） |
| 測試 | 只有實機測試（要 GPU），2040 × 1536 的合成平面（12 位元 RAW 範圍），誤差上限是提議值：`PlaneKernelsTest`，三個核心各與 CPU 版比對兩種格式的誤差並記錄 GPU 時間；`GpuGlobalAlignerTest`，法方程式與 `GradientSums` 比對、整張對齊與 `GlobalAligner` 及真值比對；`GpuTileAlignerTest`，逐塊對齊與 `TileAligner` 比對（含一塊自己移動的區域）；`GpuLowLightMergeTest`，逐張合成與 `LowLightMerge` 比對；`GpuFocusStackTest`，候選 A、B 與 CPU 比對（`BracketScene` 的合成焦點包圍）；`GpuStackGuardTest`，`StackGuard` 的保留／退回與 CPU 比對；`GpuDevelopTest`，解碼與 CPU 逐位元比對、輸出與 `Render.toArgb` 比對、銳化與 `Sharpen.apply` 逐位元比對（合成的 GBRG RAW 由 `RawScene` 產生，含列尾補齊、各格黑位、剪切與陰影表）。對齊與合成的測試用 `AlignScene`：各尺度都有紋理、加雜訊、已知縮放與位移的場景。執行：`gradlew :core:gpu:connectedDebugAndroidTest`，結果看 logcat 的 `PlaneKernelsTest`、`GpuGlobalAlignerTest`、`GpuTileAlignerTest`、`GpuLowLightMergeTest`、`GpuDevelopTest`、`GpuFocusStackTest`、`GpuStackGuardTest` |
