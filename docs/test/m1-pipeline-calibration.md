# M1 手動白平衡管線測試（Pixel 10 Pro）

2026-09-28 · 狀態：已完成（管線驗證；不是水下校正）

roadmap M1 要求「校正表先放陸上值，只用來驗證管線」。維護者同意改用室內檯燈取代日光。沒有灰卡，以白紙為目標。照片留在手機上，只把位元組串流進記憶體計算比值。

## 1. 方法

1. debug 版以 `am start ... --es depthBand DEEP` 選沒有校正值的深度段，走自動白平衡（ADR-0002 補充），對白紙拍照，讀拍攝結果中實體鏡頭的 `COLOR_CORRECTION_GAINS` 與 `COLOR_CORRECTION_TRANSFORM`。
2. 每顆鏡頭取 3 張的增益平均與矩陣，寫進 `blazer.json` 的 `calibration`（淺水段、無濾鏡、無潛水燈）。
3. 不帶參數啟動（淺水段）走手動白平衡，比較回報值與請求值，並與自動白平衡交錯拍攝比較成品色彩。
4. 色彩比值：取中央 50% 面積，sRGB 線性化後算 R/G、B/G（同 mvp-acceptance.md 的灰卡算法）。

## 2. 讀數穩定度

光線穩定後（17:33 起），每顆鏡頭 3 張的增益離散度 ≤ 0.06%，矩陣 3 張完全相同。所有值都來自實體鏡頭的結果（`getPhysicalCameraTotalResults`），預覽測光用同一查法。

17:24 第一次讀取時窗外天光仍在變化：固定參數的手動照片 B/G 每分鐘下降約 0.01–0.014，鏡頭 3、9 的 B 增益在 17:24 與 17:38 之間相差 1.9–2.7%。那一組數值已作廢，最終值取自 17:38 的讀取。

## 3. 手動路徑

| 項目 | 結果 |
| --- | --- |
| `CONTROL_AWB_MODE`（回報） | 0（OFF），鏡頭 2、3、9 都是 |
| 增益：回報 − 請求 | ≤ 1.1 × 10⁻⁷（浮點精度） |
| 矩陣：回報 − 請求 | 0 |

發現並修正：矩陣原本以分母 10000 的有理數寫入。HAL 以 1/256 為單位並朝 0 截斷，例如 2.02734375 寫成 2.0273 後被截成 2.0234375，部分元素少一格（0.2–0.9%）。改用分母 65536 後，1/256 格點可以精確表示，自動白平衡讀到的矩陣可以原樣套回。

## 4. 手動與自動的成品色彩（交錯拍攝）

| 鏡頭 | 自動 R/G | 手動 R/G | 自動 B/G | 手動 B/G |
| --- | --- | --- | --- | --- |
| 2 | 0.996–1.028（6 張，其中 5 張 0.996–1.000） | 1.017–1.019（5 張） | 0.911–0.923 | 0.903–0.909 |
| 3 | 1.022、1.036 | 1.056、1.057 | 0.850、0.853 | 0.843、0.844 |
| 9 | 1.102、1.104 | 1.095、1.095 | 0.878、0.880 | 0.878、0.879 |

套用相同的增益與矩陣，鏡頭 9 與自動白平衡幾乎一致；鏡頭 2、3 的手動 R/G 穩定高出約 2–3%，B/G 低約 1%。自動白平衡本身也有約 3% 的波動。差異都在 FR-91 的 5% 門檻以內，但原因未知：可能是 ISP 在自動模式下還有增益與矩陣以外的處理（推測，未驗證）。這會影響「以自動白平衡讀數當校正值」的做法，G4 校正時應直接以灰卡量測結果回算，不依賴自動白平衡讀數。

## 5. 其他發現

- 開機後立刻按快門：原本拋出「no metered preview frame yet」，並把相機狀態標成 FAILED，之後拍照成功也不清除，狀態列一直顯示錯誤。已改為等待第一幀測光（上限 1 秒），且拍照成功會清除錯誤。
- 開機後前 3 張檔案約 1.1 MB，之後約 1.65 MB，ISO 相同；推測是連續對焦尚未收斂。NFR-4 要求按下即拍，不等對焦，只記錄不處理。
- logcat 主緩衝區只有 256 KiB，相機 HAL 的 log 很快把舊紀錄沖掉；兩次以為漏拍，實際照片都有寫入。之後的實機測試改為在背景把 log 持續寫進檔案。
