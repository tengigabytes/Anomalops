# M9 前置：FR-17 上 GPU（ADR-0017 第 4 步）

2026-10-02 · 狀態：進行中；均方差最佳化第一輪完成（快 2.8–5.9 倍）；GPU 時脈多半停在最低檔，原因待查

手機 blazer（Pixel 10 Pro），溫度狀態 0。量法同 [m9-gpu-trial.md](m9-gpu-trial.md)：`:app` 的 `experiment/GpuBenchmark`，暫時改成非 debug 版（沒有提交，量完已裝回 debug 版），5 次取中位數。

## 1. 均方差的寫法

第 3 步每個執行緒只算一點，每 256 點就要在共享記憶體做一次 8 步的加總。改成每個執行緒走 8 列（16 × 16 的工作群組），加總的負擔由 8 點分攤。其他形狀（16 × 16 走 1 或 32 列、8 × 8、4 × 4）都比較慢。改用 `textureGather` 一次取 4 個像素、拿掉 `precise`，時間都沒有明顯變化。結果仍與 CPU 相同（相對差 ≤ 1.1 × 10⁻⁷，最佳候選相同）。

| 工作量 | CPU | 第 3 步 GPU | 現在 GPU（有前景畫面） |
| --- | --- | --- | --- |
| 81 個候選，金字塔第 2 層（510 × 384），每點都算 | 134.3 ms | 71.4 ms | 22.6 ms |
| 27 個候選，第 0 層（2040 × 1536），每隔一點（整張對齊在第 0 層的搜尋） | 177.3 ms | — | 64.2 ms |

## 2. GPU 時脈

- GPU 的頻率檔位是 198–1094 MHz，調速器是 `precise_ondemand`。持續跑均方差約 4 s，同時每 0.05 s 讀一次 `cur_freq`：有前景畫面時 150 筆裡 117 筆是 396 MHz，最高檔 1094 MHz 只有 13 筆；沒有前景畫面時差不多（107 筆 396 MHz）。取樣期間有一部分 GPU 是閒著的，所以比例只能參考。
- 有前景畫面（`-e foreground true`，開一個本程序的 activity）時，均方差約快 1.2–2.4 倍；但同一項目在不同次執行之間也會差到 1.5 倍。
- 推測：GPU 大部分時間跑在最高頻率的約三分之一。持續工作時調速器沒有把頻率拉上來的原因不明，可能和每次呼叫都等 CPU 讀回結果（GPU 斷斷續續）有關。之後可試：一次送出整張對齊的所有層級、最後才讀回；或用 Android 的效能提示（ADPF）回報工作量。
- 推測：照現在的速度，一張的整張對齊加逐塊對齊在 GPU 上約 0.3–0.5 s，五張（四張要對齊）約 1.2–2 s，加上合成、顏色與輸出，FR-17 的 3 s 很緊。
