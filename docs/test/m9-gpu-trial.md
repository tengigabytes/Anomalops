# M9 前置：GPU 試作（ADR-0017 第 3 步）

2026-10-02 · 狀態：三支著色器完成；32 位元版與 CPU 逐位元相同；速度只快 1–3.6 倍，均方差要再最佳化

手機 blazer（Pixel 10 Pro，PowerVR DXT-48-1536），Android 17，溫度狀態 0。影像是程式產生的平滑紋理，2040 × 1536（12.5 MP RAW 的半尺寸平面），數值 0–4000（12 位元 RAW 範圍）。正確性是 `:core:gpu` 的 `PlaneKernelsTest`；速度是 `:app` 的 `experiment/GpuBenchmark`，暫時把 `:app` 的 debug 建置改成非 debug 版量（沒有提交，量完已裝回 debug 版），每項先跑一次暖身，再跑 5 次取中位數，GPU 時間在 `glFinish` 之後量。

## 1. 誤差（和 `:core:imaging` 的 CPU 函式比）

| 著色器 | 對應的 CPU 函式 | 32 位元（R32F） | 半精度（RGBA16F 的紅色通道） |
| --- | --- | --- | --- |
| 減半 | `Plane.half` | 逐位元相同 | 最大 3.43、平均 −1.27 |
| 重新取樣（整張變換） | `FrameAligner.warp` | 逐位元相同，NaN 位置相同 | 最大 3.97、平均 −1.43 |
| 重新取樣，硬體雙線性 | 同上 | （32 位元不能硬體內插） | 最大 7.18、平均 −1.38 |
| 均方差，81 個候選 | `meanSquaredDiff` | 81 個值都相同 | 相對誤差最大 0.079%，最佳候選相同 |

單位是 RAW 值。

- **要用 `precise` 才逐位元相同。** 沒有它時，GPU 把乘法和加法合併成一次捨入，重新取樣的位置在約三分之一的像素差一個浮點最小單位（2040 寬時約 0.00012 像素），值最多差 0.16。加上 `precise` 之後位置與值都和 CPU 一樣。`precise` 在 GLSL ES 3.10 要 `GL_EXT_gpu_shader5`（3.20 內建）；Pixel 10 Pro 有，已列入能力表。
- 半精度的誤差都是往零捨入造成的：輸入與輸出各捨一次，相對誤差上限 2 × 2⁻¹⁰（約 0.2%），實測 0.19%，一律偏小。
- 硬體雙線性的誤差是手動內插的兩倍左右（相對 1.2%）。推測是硬體內插權重的位數少；對齊與合成不採用。

## 2. 速度（非 debug 版，中位數）

| 步驟 | CPU | GPU 32 位元 | GPU 半精度 |
| --- | --- | --- | --- |
| 上傳一個平面（12.5 MB） | — | 8.4 ms | 33.5 ms（含轉換） |
| 下載一個平面 | — | 15.2 ms | 38.4 ms |
| 減半 | 2.5 ms | 2.6 ms | 11.1 ms |
| 重新取樣 | 31.3 ms | 8.8 ms | 39.0 ms |
| 重新取樣，硬體雙線性 | — | — | 36.2 ms |
| 均方差，81 個候選（金字塔第 2 層，510 × 384） | 132.5 ms | 71.4 ms | 82.2 ms |

- **GPU 只快 1–3.6 倍。** 減半沒有變快，CPU 版本來就快。重新取樣快 3.6 倍；均方差只快 1.9 倍。推測均方差慢在共享記憶體的逐步加總（每 256 點要 8 次同步）與整數除法；→ 第 4 步改成一個執行緒處理 8 列後快 2.8–5.9 倍，見 [m9-gpu-fr17.md](m9-gpu-fr17.md)。
- **目前的半精度比 32 位元慢又不準。** 單通道放在 RGBA16F，一個像素占 8 位元組，比 R32F 的 4 位元組還多，讀寫都較慢。半精度只有在一個像素放滿 4 個通道（R、G、B、亮度）時才省記憶體，要到第 4 步做顏色時再評估。
- 推測：對齊一張在 CPU 上約 1.4 s，大部分在算均方差；GPU 若只快 2 倍，FR-17 五張含顏色 ≤ 3 s 仍達不到。第 4 步要先把均方差的速度提高（已開始，見 m9-gpu-fr17.md）。

## 3. 對 ADR-0017 的影響（2026-10-02 維護者已依建議決定）

- 平面格式：建議先全部用 32 位元（R32F），與 CPU 逐位元相同，測試也最嚴；半精度留到第 4 步做顏色時，以 4 通道一起放的形式重新評估。
- `precise`：建議接受 `GL_EXT_gpu_shader5`（或 GLES 3.2）這項需求。Pixel 6–9 是否支援尚未確認，M11 用 `:tools:probe` 逐一偵測。
