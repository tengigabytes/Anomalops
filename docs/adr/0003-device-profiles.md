# ADR-0003 每型號能力表與校正表以資料檔描述

2026-09-28 · 狀態：已採納（產品擁有者 2026-09-28 確認）

## 背景

NFR-9 要求新增 Pixel 6 Pro 到 11 Pro 時只補表與實拍校正，不改主程式。[需求第 8 節](../product/requirements/08-risks.md)也把「各代 Pixel 的 Camera2 支援程度」列為首要假設，要先寫能力偵測工具。

## 決策

每個型號一個資料檔：`assets/device-profiles/<device>.json`，分兩部分。

**能力（capabilities）**：由能力偵測工具自動產生，不手寫。

- 邏輯與實體鏡頭 ID、焦距、視角、最近對焦距離
- hardware level、capabilities、可用的 AF / AE 模式、ISO 與曝光時間範圍
- RAW\_SENSOR、JPEG、JPEG\_R 的可用尺寸
- 可用的擷取請求鍵
- 裝置上的感測器種類（FR-45）

**校正（calibration）**：由校正潛水產生。每一筆以「實體鏡頭 × 深度段 × 已裝濾鏡 × 潛水燈模式」為鍵，內容包含：

- 4 個增益與 3×3 色彩矩陣
- 來源資訊：日期、灰卡種類、潛點、深度

**其他規則**

- 檔案帶 `schemaVersion`，以 JSON Schema 驗證，驗證寫成單元測試。
- 以 `Build.DEVICE` 選檔。找不到對應檔案時，執行時即時偵測能力；校正值借用最接近的已校正型號，並標記為「未校正」（[需求第 8 節](../product/requirements/08-risks.md)第 2 列）。
- 能力偵測工具是 `:tools:probe` 模組（ADR-0007），把結果匯出為 JSON，同時產出人看得懂的摘要表。

## 不採用的選項

- **型號差異寫在程式裡**：每加一個型號就要改程式，違反 NFR-9。
- **全部執行時偵測、不存檔**：能力部分做得到，但校正值必須實拍取得，一定要有地方存；而且能力表存進 repo，才能拿來比較不同型號的差異。

## 後果

- 新增型號的流程是：跑偵測工具 → 提交 JSON → 做校正潛水 → 補校正值。
- 深度段的邊界（[需求第 9 節](../product/requirements/09-open-items.md)待決）也放在資料檔，改邊界不需改程式。
- 能力表裡有 `Build.DEVICE` 與鏡頭硬體資訊，但不含個人資料，可以公開。

## 驗證

- G0：在 Pixel 10 Pro 跑偵測工具並提交結果，確認 schema 涵蓋 ADR-0001、0002、0004、0005、0009 需要的所有欄位。
- NFR-9 驗收：新增第二個型號時，只有 `assets/device-profiles/` 有變動。
