# ADR-0016 多幀影像處理放在新模組 `:core:imaging`

2026-10-01 · 狀態：已採納（維護者 2026-10-01 選定）

## 背景

v1.1 起有好幾項功能要處理同一組連拍的多張影像：FR-17 低光多幀合成、FR-33 景深合成、之後的 FR-18、FR-19 超解析。它們都要先把各張對齊，再依各自的方式合成（ADR-0015）。

ADR-0007 的模組表裡沒有「影像處理」這個職責：`:core:camera` 管 Camera2 工作階段與請求，`:core:store` 管寫檔與堆疊索引。把對齊與合成塞進其中一個，會讓它的職責變大，而且兩者都是 Android 函式庫，純運算的測試也要連 Android 一起編譯。

## 決策

- 新增 `:core:imaging`，與 `:core:profile` 一樣是純 Kotlin/JVM 模組，不依賴 Android，也不依賴其他專案模組。輸入是 `Plane`（單通道線性數值）等自己的資料型別；從 Camera2 的 `Image` 轉成 `Plane` 的程式放在呼叫端。
- 多幀的對齊、合成、景深合成都放在這裡，依功能分套件（`align/`，之後的 `merge/`、`stack/`）。
- 依賴規則：`:app` 可以依賴 `:core:imaging`；`:core:imaging` 不依賴任何專案模組。`scripts/check_module_deps.py` 已加入這條規則。
- 這裡的程式是 CPU 版的參考實作。FR-17 要求 GPU 執行；GPU 版之後另寫，並以這裡的結果比對。

## 不採用的選項

- **放進 `:core:camera`**：相機模組的職責變大，純運算的測試也要連 Android 函式庫編譯。
- **放進 `:core:store`**：儲存模組的職責不符；FR-69 淘選的清晰度計算目前在那裡，之後可考慮移過來。

## 後果

- ADR-0007 的模組表多一列，以本 ADR 補註。
- 單元測試在任何電腦上都能快速執行，CI 的 `test` 工作會一併跑。
- 手機上的實際速度要另外量：陸上桌機 JVM 對齊一張 2040 × 1536 的合成影像約 0.8 s，手機上推測會更慢，要在實機量過再決定是否先做 GPU 版。

## 驗證

- 對齊的正確性由 `:core:imaging` 的單元測試以合成影像驗證（已知位移、縮放、模糊、局部移動）。
- 實拍的對齊誤差與手機上的耗時，在 FR-17、FR-33 接上後以實機量測。
