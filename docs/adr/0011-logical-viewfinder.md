# ADR-0011 v1.1 取景與錄影改用 logical 串流，連續變焦跨鏡頭

2026-09-28 · 狀態：提議（維護者 2026-09-28 暫定採用做法 1，待實驗確認後改為已採納）

## 背景

v1.1 的錄影與變焦需求（FR-13、FR-13a）：

- 拍照與錄影共用同一取景畫面，各有獨立按鈕，不切換模式；按下錄影鍵即開始錄影。
- DV 式變焦條；錄影時在超廣角、主鏡頭、望遠之間連續變焦，換鏡頭不停頓，與 Pixel 原生相機相同。
- 拍照倍率跟隨預覽倍率，照片不得降低解析度。

v1.0 的做法是每個工作階段只用一顆鏡頭的實體串流（ADR-0001、`setPhysicalCameraId`），好讓每顆鏡頭套用自己的水下校正值（ADR-0002）。在這個做法下，換鏡頭要重建工作階段，實測 240–400 ms，影片與預覽會停住。

logical camera 能以 `CONTROL_ZOOM_RATIO` 讓 HAL 自己換鏡頭：API 文件的範例即為「0.5× 縮小換到超廣角」；G0 實測 Pixel 10 Pro 的對照為 0.51× → 超廣角（ID 3）、1–5× → 主鏡頭（ID 2）、10× → 望遠（ID 4），結果中的 `LOGICAL_MULTI_CAMERA_ACTIVE_PHYSICAL_ID` 回報目前的鏡頭。

## 決策（提議）

自 v1.1 起，取景工作階段一律使用 logical 串流：

- 預覽與錄影共用一路 PRIVATE 串流，最大 1920 × 1440（`STREAM_USE_CASE_PREVIEW_VIDEO_STILL`，STREAM_USE_CASE 保證表的 s1440p），另接全尺寸照片輸出（JPEG\_R，必要時 RAW）。按下錄影鍵只把編碼器加入重複請求，不重建工作階段。
- 變焦只改 `CONTROL_ZOOM_RATIO`，由 HAL 選鏡頭。
- 白平衡：logical 串流上各實體鏡頭的個別設定不生效（`createCaptureRequest(int, Set)` 的文件：只有工作階段含該實體鏡頭的輸出時才套用），因此只送一組增益與矩陣，依結果回報的目前鏡頭即時換成該鏡頭的校正值；可依變焦對照表在跨越門檻的同一個請求預先換值，縮短錯用校正值的幀數。
- 拍照倍率等於預覽倍率，照片輸出維持全尺寸。

v1.0 的拍照管線（實體串流、每鏡頭一個工作階段）不變。

## 不採用的選項

- **取景用實體串流，錄影時換成 logical 工作階段**：按下錄影鍵要重建工作階段（實測約 240 ms 以上），違反「不切換模式」。
- **全用實體串流**：錄影換鏡頭停頓 0.25–0.5 s（推測，依 M1、M2 的切換時間），違反「換鏡頭不停頓」。

## 後果

- ADR-0001 的「直接指定實體鏡頭」與 ADR-0002 的「每個實體鏡頭套用自己的校正值」在 v1.1 取景中改為「依 HAL 選定的鏡頭換值」；採納時兩份 ADR 需補註或另寫取代的 ADR。
- 換鏡頭瞬間可能有數幀用錯校正值，影片上可見短暫色偏；幅度取決於水下各鏡頭校正值的差異（陸上量得主鏡頭與超廣角增益差 2–3%，水下待 G4）。
- HAL 也可能依光線、對焦距離決定是否換鏡頭，本 APP 無法強制；微距（ID 9，超廣角中央裁切）無法以變焦倍率選到，微距預設的做法要另定。
- 中間倍率（例如 3×）的照片由 HAL 決定裁切讀出或放大，輸出尺寸為全尺寸，實際細節可能低於原生倍率（推測）。
- logical 串流的 RAW 來自當下的實體鏡頭，DngCreator 所需的特性（色彩矩陣等）要對應到該鏡頭，ADR-0005 的寫出流程需調整（推測）。

## 驗證（採納前，實機實驗）

- logical 串流跨鏡頭連續變焦是否平順（幀間隔、有無停格），與原生相機比較。
- 換鏡頭時校正值錯用的幀數與色偏幅度；預先換值能縮短多少。
- logical 串流在 1×、2×、5×、10× 與中間倍率拍的照片：輸出尺寸、實際細節（解析度卡）與實體串流比較。
- 「共用預覽／錄影一路 + 全尺寸 JPEG\_R（+ RAW）」能否實際建立（M2 已知查詢結果不可靠，且 JPEG\_R 在 HAL 內部可能多占串流），30 fps 與 60 fps 各測。
- 錄影中拍照（`TEMPLATE_VIDEO_SNAPSHOT`，同時輸出到編碼器）是否造成影片掉幀或曝光跳動。
