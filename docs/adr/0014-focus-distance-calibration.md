# ADR-0014 對焦距離校準與包圍步進

2026-09-30 · 狀態：提議

## 背景

FR-33 焦點包圍要在指定的距離範圍內，以不留空隙的步進連拍；FR-36 長焦微距要顯示距離提示。兩者都要把 `LENS_FOCUS_DISTANCE`（屈光度，D）換成實際距離，準不準由 `LENS_INFO_FOCUS_DISTANCE_CALIBRATION` 決定：

- `CALIBRATED`：屈光度就是實際距離的倒數，可直接用。
- `APPROXIMATE`：單位是屈光度，但與實際距離只大致相符。
- `UNCALIBRATED`：只保證數值單調，0 是無限遠，與距離沒有對應。

Pixel 10 Pro 的 ID 2、3、9 都是 `APPROXIMATE`（[m4-af-timeline.md](../test/m4-af-timeline.md)）；望遠 ID 4、6 與 2× 裁切 ID 5 未記錄。Pixel 6 Pro 到 11 Pro 各型號、各鏡頭的值未知，而且可能隨系統更新改變。

## 決策（提議）

**1. 執行時查詢，資料檔只放實測值**

- 每次開啟鏡頭時讀取 `LENS_INFO_FOCUS_DISTANCE_CALIBRATION`、`LENS_INFO_MINIMUM_FOCUS_DISTANCE`、`LENS_INFO_HYPERFOCAL_DISTANCE`、`SENSOR_INFO_PHYSICAL_SIZE`，不寫死在程式或資料檔裡。
- API 查不到的實測結果（屈光度對實際距離的校正表），和白平衡校正表一樣放在 `assets/device-profiles/`（ADR-0003、NFR-9）。校正表記錄量測時的校準類型與最近對焦值；執行時讀到的值與它不一致（例如系統更新後改變），就視為沒有校正表。
- 這是對 NFR-9「能力一律執行時查詢、不可寫死」的解讀：能力旗標與規格值在執行時查詢，資料檔只放 API 無法提供的實測資料。

**2. 依校準類型處理**

| 校準類型 | 有校正表 | 沒有校正表 |
| --- | --- | --- |
| `CALIBRATED` | 用校正表（抽查用） | 直接以屈光度步進 |
| `APPROXIMATE` | 以校正表換算 | 以屈光度步進，距離提示標示「約」；包圍多疊一張的重疊（提議） |
| `UNCALIBRATED` | 以校正表換算 | 不提供 FR-33 與 FR-36 的距離提示；FR-32 手動滑桿仍可用 |

**3. 包圍步進依景深估算**

- 放大倍率遠小於 1 時，景深以屈光度計約等於超焦距屈光度的 2 倍，與對焦距離無關（推算，薄透鏡近似）。步進取「景深 × 重疊係數」，重疊係數初值 0.7（提議）。
- 近距時放大倍率不再遠小於 1，上式高估景深；步進改以放大倍率修正（公式在實作時寫進 KDoc，以待測清單的實測校正）。
- 張數由「主體深度 ÷ 步進」決定，上限依 FR-33；超出上限時，照上限拍並提示「景深不足，建議退遠」。

**4. 校正流程（每型號、每顆會用到的鏡頭，陸上）**

1. 腳架固定手機，解析度卡或印刷頁沿導軌放在已知距離：從最近對焦距離到其 3 倍，至少 8 個點（提議）。
2. 每個距離以 `CONTROL_AF_MODE_OFF` 由近到遠掃描 `LENS_FOCUS_DISTANCE`，步進取超焦距屈光度的 1/4；每一步取 RAW 中央區塊的拉普拉斯變異數。
3. 每個距離取清晰度最高的屈光度，擬合「屈光度 → 實際距離」曲線，寫入能力表。
4. 通過標準見 [macro-stacking-test-plan.md](../test/macro-stacking-test-plan.md) T4。

**5. 水中**：平面鏡窗後的主體看起來在實際距離約 1/1.33 處（推測，薄透鏡與近軸近似）。陸上校正表描述的是鏡頭看到的「視距」，水中顯示距離時再乘上比例；比例以水盆實測（T8）。

## 不採用的選項

- **把各型號的校準類型與最近對焦寫進能力表當規格**：系統更新可能改變，而且違反「執行時查詢」。
- **一律以 AF 掃描找最清晰的距離，不用校正表**：水下低對比時 AF 不可靠（FR-35），包圍也來不及。

## 後果

- probe 要補收 `SENSOR_INFO_PHYSICAL_SIZE`（等效光圈與畫面寬的換算需要）；能力表結構會增加校正表欄位，`ProfileValidator` 同步修改。
- 每個新型號多一項陸上校正工作（M11），不需下水。
