# ADR-0014 對焦距離校準與包圍步進

2026-09-30 · 狀態：提議

## 背景

FR-33 焦點包圍要在指定的距離範圍內，以不留空隙的步進連拍；FR-36 長焦微距要顯示距離提示。兩者都要把 `LENS_FOCUS_DISTANCE`（屈光度，D）換成實際距離，準不準由 `LENS_INFO_FOCUS_DISTANCE_CALIBRATION` 決定：

- `CALIBRATED`：屈光度就是實際距離的倒數，可直接用。
- `APPROXIMATE`：單位是屈光度，但與實際距離只大致相符。
- `UNCALIBRATED`：只保證數值單調，0 是無限遠，與距離沒有對應。

Pixel 10 Pro 後置 6 個實體 ID 都是 `APPROXIMATE`（[m4-af-timeline.md](../test/m4-af-timeline.md)；4、5、6 由 2026-09-28 的 probe 報告補讀，[g0-blazer.md](../test/g0-blazer.md)）。Pixel 6 Pro 到 11 Pro 各型號、各鏡頭的值未知，而且可能隨系統更新改變。

## 決策（提議）

**1. 執行時查詢，資料檔只放實測值**

- 每次開啟鏡頭時讀取 `LENS_INFO_FOCUS_DISTANCE_CALIBRATION`、`LENS_INFO_MINIMUM_FOCUS_DISTANCE`、`LENS_INFO_HYPERFOCAL_DISTANCE`、`SENSOR_INFO_PHYSICAL_SIZE`，不寫死在程式或資料檔裡。
- API 查不到的實測結果（屈光度對實際距離的校正表），和白平衡校正表一樣放在 `assets/device-profiles/`（ADR-0003、NFR-9）。校正表記錄量測時的校準類型與最近對焦值；執行時讀到的值與它不一致（例如系統更新後改變），就視為沒有校正表。
- 這是對 NFR-9「能力一律執行時查詢、不可寫死」的解讀：能力旗標與規格值在執行時查詢，資料檔只放 API 無法提供的實測資料。

**2. 依校準類型處理**

| 校準類型 | 有校正表 | 沒有校正表 |
| --- | --- | --- |
| `CALIBRATED` | 用校正表（抽查用） | 直接以屈光度步進 |
| `APPROXIMATE` | 以校正表換算 | 以屈光度步進，距離提示標示「約」；包圍多疊一張的重疊（提議） |
| `UNCALIBRATED` | 以校正表換算 | 不提供 FR-33 與 FR-36 的距離提示；FR-32 手動滑桿仍可用 |

**3. 包圍步進依景深估算**

- 放大倍率遠小於 1 時，景深以屈光度計約等於超焦距屈光度的 2 倍，與對焦距離無關（推算，薄透鏡近似）。步進取「景深 × 重疊係數」，重疊係數初值 0.7（提議）。
- 近距時放大倍率不再遠小於 1，上式高估景深；步進改以放大倍率修正（公式在實作時寫進 KDoc，以待測清單的實測校正）。
- 張數由「主體深度 ÷ 步進」決定，上限依 FR-33；超出上限時，照上限拍並提示「景深不足，建議退遠」。

**4. 校正流程（每型號、每顆會用到的鏡頭，陸上）**

1. 腳架固定手機，解析度卡或印刷頁沿導軌放在已知距離：從最近對焦距離到其 3 倍，至少 8 個點（提議）。
2. 每個距離以 `CONTROL_AF_MODE_OFF` 由近到遠掃描 `LENS_FOCUS_DISTANCE`，步進取超焦距屈光度的 1/4；每一步取 RAW 中央區塊的拉普拉斯變異數。
3. 每個距離取清晰度最高的屈光度，擬合「屈光度 → 實際距離」曲線，寫入能力表。
4. 通過標準見 [macro-stacking-test-plan.md](../test/macro-stacking-test-plan.md) T4。

**5. 水中**：平面鏡窗後的主體看起來在實際距離約 1/1.33 處（推測，薄透鏡與近軸近似）。陸上校正表描述的是鏡頭看到的「視距」，水中顯示距離時再乘上比例；比例以水盆實測（T8）。

## 不採用的選項

- **把各型號的校準類型與最近對焦寫進能力表當規格**：系統更新可能改變，而且違反「執行時查詢」。
- **一律以 AF 掃描找最清晰的距離，不用校正表**：水下低對比時 AF 不可靠（FR-35），包圍也來不及。

## 後果

- probe 早已收集 `SENSOR_INFO_PHYSICAL_SIZE`（2026-10-01 查證；原本誤寫為要補收），能力表尚未收錄；執行時直接查詢即可。能力表結構會增加校正表欄位，`ProfileValidator` 同步修改。
- 每個新型號多一項陸上校正工作（M11），不需下水。

## 驗證

[macro-stacking-test-plan.md](../test/macro-stacking-test-plan.md) T2–T5、T8、T10：各鏡頭的校準類型、實際最近對焦、校正曲線與殘差、感光元件尺寸、水中視距比例、對焦呼吸。

2026-09-30 T9 結果（[m9-macro-land.md](../test/m9-macro-land.md) 第 3 節）：6 張一張換一個距離的 `captureBurst`，感光跨度約 170 ms，但 6 張都標 MOVING，回報的對焦距離比請求超前兩張。第 3 節的步進要以實測的每張對焦位置為準，不能假設每張都在請求的距離上；是否改成每個距離停兩到三幀，由 T7、T10 的影像判斷後決定。

2026-10-01 T4 結果（[m9-macro-land.md](../test/m9-macro-land.md) 第 5 節，30–60 cm 六點）：主鏡頭與望遠的 APPROXIMATE 讀數都比實際遠約 0.06–0.08 D，斜率幾乎是 1，一個常數偏移就能修正大部分。修正後望遠仍有約 0.02 D 的殘差（受捲尺精度限制），與其景深 0.049 D 相比不可忽略，因此第 2 節「APPROXIMATE 多疊一張」的做法保留。AF 鎖定的位置（主鏡頭 50 cm 時偏 0.24 D）不能當距離量測用，第 4 節的校正流程維持以細掃取峰值。

2026-10-01 補註：第 3 節的包圍步進已實作為 `:core:camera` 的 `focus/BracketPlanner`（純邏輯，JVM 測試 8 個）。近距修正寫成景深（屈光度）＝ 2 × 超焦距屈光度 ÷（1 + m），m ＝ f ÷（s − f），由薄透鏡推導，放大倍率越大、以屈光度計的景深越窄，與第 3 節「上式高估景深」一致。APPROXIMATE 且沒有校正表時多一張、UNCALIBRATED 且沒有校正表時不規劃、校正偏移（T4 的約 0.07 D）以「實際 ＝ 回報 ＋ 偏移」換算、主體近於最近對焦時從極限起拍並標示、超過張數上限時涵蓋主體中段並標示 truncated。尚未接上介面與相機。

2026-10-01 補註（維護者同意撰寫者的提議）：校正表照第 1 節放在 `assets/device-profiles/` 的 `focusCalibration` 區段（手寫，`probe_to_profile.py` 重新產生時保留）。blazer 已放入 T4 的三筆擬合（鏡頭 2、4、6；30–60 cm 六點），並記錄量測時的校準類型與最近對焦；`ProfileValidator` 檢查最近對焦與能力表一致。`:core:camera` 以 `FocusCalibrationTable.fromProfile` 讀取；望遠兩筆未達 T4 門檻，包圍照樣多疊一張。尚未接上相機。
