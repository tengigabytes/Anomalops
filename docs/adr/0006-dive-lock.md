# ADR-0006 潛水鎖定：螢幕固定 + 沉浸模式 + 鎖定畫面上顯示

2026-09-28 · 狀態：已採納（產品擁有者 2026-09-28 確認）

## 背景

手機在殼內時：
- 系統手勢、通知、誤觸都可能讓 APP 離開前景，而人在水下無法把防水殼打開來修復。

需求的要求：
- FR-51：全螢幕、鎖方向、最高亮度、屏蔽通知與手勢，只能長按 3 s 解鎖。
- FR-56：系統鎖定後仍能直接回到相機。
- NFR-1：崩潰後自動回到潛水鎖定。

## 決策

**進入鎖定時，同時做以下幾件事**

| 機制 | 用途 |
| --- | --- |
| `Activity.startLockTask()` | 進入「螢幕固定」，擋住返回與主畫面手勢（推測：APP 不是裝置擁有者時，系統會要求使用者確認一次） |
| `WindowInsetsController` 隱藏系統列，行為設為 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` | 全螢幕 |
| `setShowWhenLocked(true)`、`setTurnScreenOn(true)` | FR-56 |
| `FLAG_KEEP_SCREEN_ON`、`screenBrightness = 1.0f` | 不休眠、最高亮度 |
| 固定 `requestedOrientation` | 鎖方向 |
| `setSystemGestureExclusionRects` 涵蓋快門條 | 降低邊緣手勢誤判（推測系統限制每側最多 200 dp） |

**解鎖**：APP 內長按 3 s，呼叫 `stopLockTask()`，恢復一般模式。

**通知**：推測螢幕固定期間無法下拉通知欄；抬頭通知是否仍會出現，要實機確認。如果會，就在進入鎖定時開啟勿擾模式，這需要使用者先授予 `ACCESS_NOTIFICATION_POLICY`。

**崩潰重啟**：
- 設定未捕捉例外處理器，排程在 3 s 內重新啟動 Activity。
- Android 10 起限制背景啟動 Activity；推測需要使用者授予「顯示在其他應用程式上層」權限，才能在崩潰後自動重啟。
- 使用者在設定中「強制停止」後，推測 APP 無法自行重啟，因此 NFR-1 的範圍已改為只涵蓋崩潰（mvp-scope.md 第 6 節第 6 項）。

## 不採用的選項

- **以裝置擁有者身分設定 Lock Task 白名單**：推測要先移除裝置上所有帳號，或恢復原廠設定，才能設定裝置擁有者，不適合個人手機。
- **只用沉浸模式**：從邊緣滑一下就會叫出系統列，再滑一次就可能離開 APP。

## 後果

- 下水前要做一次授權：螢幕固定確認、勿擾存取（若需要）、顯示在上層。v1.0 沒有 FR-58 下水前檢查清單（P1），所以這些授權在第一次進入鎖定時引導完成。
- 在鎖定狀態下按電源鍵關閉螢幕、再喚醒時，推測螢幕固定仍然有效，而且會直接顯示本 Activity，要實機確認。
- 螢幕固定期間，推測系統另有一組解除固定的手勢（例如上滑並按住）。它是否會在殼內被誤觸發，要在泳池測試中確認。

## 驗證

G1 以陸上實機確認以下各點：
1. 非裝置擁有者時 `startLockTask()` 的實際行為
2. 抬頭通知是否被擋
3. 電源鍵關開螢幕後是否仍在固定狀態
4. 崩潰後能否自動重啟，以及需要哪些權限
5. 解除固定手勢被誤觸發的難易度

結果寫回本 ADR。與推測不同時，修改決策。

2026-09-28 實機結果（Pixel 10 Pro，見 [g1-dive-lock-platform.md](../test/g1-dive-lock-platform.md)）：`startLockTask()` 會跳確認對話框，按下後才固定；固定會擋掉抬頭通知，因此不需要勿擾存取權；手機上鎖時無法進入固定；崩潰重啟要用另一個程序的跳板 Activity 讓 task 保持不空，才能保住固定（449 ms 重啟），且不需要「顯示在上層」權限。以上推測中與結果不同的部分，以此補註為準。
