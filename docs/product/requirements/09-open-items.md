# 9. 待決事項與後續版本規劃

[← 需求文件索引](README.md)

v1.0（MVP）的範圍、架構決策與驗收條件分別見 [mvp-scope.md](../mvp-scope.md)、[adr/](../../adr/README.md)、[mvp-acceptance.md](../mvp-acceptance.md)；長期里程碑見 [roadmap.md](../roadmap.md)。

以下事項需在進入設計階段前決定：

- [ ] 白平衡校正的基準：用商用灰卡，還是自製已知反射率的 PCB 白板？
- [ ] 深度分段邊界：淺 0–6 m / 中 6–15 m / 深 15 m+ 是否合理，還是依臺灣東北角與熱帶海域分兩組？
- [ ] 錄影是否需要 LOG 色彩描述檔？
- [x] APP 名稱與是否開源（tengigabytes 帳號下）。→ 2026-09-28 決定：開源，程式碼 GPL-3.0-or-later、文件 CC BY-SA 4.0；applicationId `io.github.tengigabytes.anomalops`，名稱沿用 Anomalops；Play 版以 Play Billing 提供樂捐。見[授權](../../release/licensing.md)與 [ADR-0010](../../adr/0010-flavors-and-donations.md)。
- [x] 預設檔式選 10-bit HEIC 還是 Ultra HDR JPEG？HEIC 較省空間，但分享相容性較差。→ 2026-09-28 決定：v1.0 用 JPEG\_R（不支援時 JPEG，FR-61a），10-bit HEIC（FR-61）延到 v1.1。
- [x] RAW 按需保留的觸發手勢：長按縮圖，還是快門區上方專用「保留 RAW」鍵？→ 2026-09-28 決定：長按縮圖（FR-62），泳池測試後若按不到再改。
- [ ] 雷射測距實測：需一支可看到 940 nm 的相機（舊網路攝影機或拆掉 IR 濾鏡的 Pi Camera）。
- [ ] BLE 感測模組是否由自己設計？若是，協定（FR-85）可在 v1 就定稿。
- [x] NFR-4「預設切換 ≤ 300 ms」是否也適用於需要換實體鏡頭的切換？→ 2026-09-28 G1 實測（[m1-instrumented.md](../../test/m1-instrumented.md)）：同一鏡頭的切換 143–215 ms；換鏡頭需重建工作階段，HAL 重建時間有波動，換鏡頭的 p95 為 374 ms。決定：拆成兩個門檻，同一實體鏡頭 p95 ≤ 300 ms，換實體鏡頭 p95 ≤ 450 ms（400 ms 時三次量測 394–410 ms，時過時不過）。暗處自動曝光把預覽降到 15 fps，延遲約加倍；試過把預覽固定在 30 fps，但照片會暗最多 1 EV 且偵測不到（ADR-0009 補註），因此不固定，NFR-4 只在 30 fps 的亮度下判定，暗處只記錄。
- [x] FR-16 的 DNG 驗證工具：維護者沒有 Lightroom Classic。→ 2026-09-28 決定：改用 Adobe `dng_validate` 加 darktable 開啟。
- [x] FR-68「在相簿中折成一個堆疊」的做法：v1.0 沒有 APP 內相簿（FR-71 為 P1），Google 相簿是否依檔名折疊未確認。→ 2026-09-28 決定：v1.0 只在 APP 內以 Room 索引分組，不依賴檔名慣例。
- [x] 長按快門時，按下瞬間拍的那張（NFR-4「按下即拍第一張」，JPEG\_R + RAW）是否屬於連拍堆疊？→ 2026-09-28 決定：不屬於。它是獨立的單張，RAW 照常進緩衝（FR-62）；堆疊只含按住 400 ms 後切換到連拍工作階段拍的一般 JPEG，封面是第一張連拍 JPEG（FR-68 驗收照原文）。
- [x] 錄影規格與操作（FR-13）：4K 檔案太大，維護者不拍 4K；原生相機切換拍照 / 錄影模式有時間差，容易錯過瞬間。→ 2026-09-28 決定：影片 1920 × 1440（4:3），30 / 60 fps 可設定、預設 30 fps；拍照與錄影共用取景畫面、各有獨立按鈕，不切換模式。NFR-1、NFR-2、roadmap M7 的 4K 改為 1440p。
- [x] 變焦（FR-13a）：DV 式類比變焦條，放在取景畫面下方；越過鏡頭邊界自動換鏡頭（望遠與超廣角是 Pixel 的優勢）；拍照不得以數位裁切降低解析度（望遠拍照很重要）。→ 2026-09-28 決定，版面在 M3 另行規劃。
- [x] 音量鍵：防水殼按不到。→ 2026-09-28 決定：FR-53 取消；深水觸控失效的退路改為 FR-85 BLE 外接快門（第 8 節）。
- [x] FR-13a 拍照倍率：拍照時倍率只停在原生倍率，還是跟隨預覽倍率？→ 2026-09-28 決定：跟隨預覽倍率，照片不得降低解析度（輸出維持全尺寸）。
- [x] FR-15a 半按鈕的版本 → 2026-09-28 決定：v1.1。
- [x] FR-15a 對焦未完成就放開時 → 2026-09-28 決定：等對焦鎖定後再拍。
- [x] FR-13a 錄影連續變焦的架構：logical 串流讓 HAL 換鏡頭，但不能套用各實體鏡頭的校正值（ADR-0002）。→ 2026-09-28 維護者暫定做法 1：v1.1 起取景一律用 logical 串流，錄影與拍照共用；v1.0 拍照管線不變。寫成 [ADR-0011](../../adr/0011-logical-viewfinder.md)（提議），實機實驗確認後改為已採納。
- [x] M3 畫面配置（[dive-lock-layout.md](../dive-lock-layout.md)）→ 2026-09-28 決定：直向；預設沿右側長邊，潛水鎖定 / 解鎖鍵在左上；FR-13a 變焦條、FR-15a 半按鈕、FR-13 錄影鍵在 v1.0 留白保留位置，v1.1 加入時其他元件不移動；FR-24 濾鏡設定頁併入 M3，只能在一般模式開啟。
- [x] 崩潰重啟後的 FR-45 場次 → 2026-09-28 決定：延續同一個場次，一次潛水一份紀錄（ADR-0008 補註）。
- [x] 07-housing「≥ 64 dp」以實體大小還是 dp 為準 → 2026-09-29 決定：以實體大小為準，按鍵固定 11 mm（預設顯示大小下約 69 dp）；G1 以系統預設顯示大小量測 dp（[dive-lock-layout.md](../dive-lock-layout.md) 第 5 節）。
- [x] NFR-6「同一點 200 ms 內多次觸發視為一次」的計時起點 → 2026-09-29 決定：從被接受的那一下起算；同一點持續連發時，每 200 ms 仍會再接受一次，不會永久擋住。
- [x] 系統仍在固定、但沒有 FR-45 場次紀錄時（固定後、寫入前崩潰）→ 2026-09-29 決定：仍回到潛水鎖定並開新場次，因為水下無法重新固定。
- [x] 07-housing「溫度異常上升時警示」的門檻 → 2026-09-29 決定：系統熱狀態（`PowerManager.currentThermalStatus`）達 MODERATE 以上時，下緣資訊列改為警示色並顯示「過熱」；NFR-2 要求潛水期間維持在 LIGHT 以下。G2 水浴記錄熱狀態後再檢討。
- [x] M3 介面的定位 → 2026-09-30 決定：M3 的畫面只是操作邏輯的測試版，先完善底層核心功能，外觀之後持續改進。影響：NFR-5 室內與戶外目視延到 UI 整理後再做（對比 ≥ 7 : 1 與狀態色不用藍色仍由 `DivePaletteTest` 檢查；5 m 水下照舊在 G4）；NFR-10 字串審查在 UI 字串改寫後重做。UI 整理排在哪個里程碑尚未決定。
- [x] 潛水鎖定中連續崩潰時怎麼辦？→ 2026-09-30 決定：不再重啟，連續崩潰八成是程式本身有問題。第一次崩潰照 NFR-1 重啟；重啟後 60 s 內又崩潰，就不啟動跳板，改走一般的崩潰處理。task 變空後系統解除固定（[G1 平台測試](../../test/g1-dive-lock-platform.md)第 2 節），FR-45 場次在下次啟動時由 `DiveLock` 判定結束。之後手機是否隨即上鎖未測（G1 只確認 `stopLockTask()` 之後會上鎖）。已實作（`lock/CrashLoop`），維護者決定不做實機測試（[m3-test-plan.md](../../test/m3-test-plan.md) 第 4 節）。原本的考量如下：目前每次崩潰都在約 0.45–0.75 s 內重啟（NFR-1），若每次啟動都崩潰，會無限循環：畫面閃爍、耗電，FR-45 紀錄也跟著中斷。可行做法：（1）維持現狀，無限重啟；（2）退避重啟，間隔依次拉長（例如 0.3、1、3、10 s），仍保住固定；（3）30 s 內崩潰 3 次後改開不含相機的「安全畫面」，只顯示錯誤、解鎖鍵與電量，仍保住固定。建議（3）：水下無法修復，但至少畫面穩定、能解鎖、耗電低；代價是多一個畫面與一條崩潰計數。M3 泳池測試前決定。
- [x] 鎖定中系統解除固定（上滑並按住的手勢被觸發）時怎麼辦？→ 2026-09-30 決定：不違背系統，不重新固定；APP 偵測到固定解除時視同解鎖，結束 FR-45 場次並回到一般模式，狀態與系統一致。已實作（`lock/PinWatcher` 鎖定中每秒檢查固定狀態），維護者決定不做實機測試（[m3-test-plan.md](../../test/m3-test-plan.md) 第 4 節）。原本的考量如下：解除後系統列與返回手勢恢復作用，FR-51 的保護失效；APP 目前仍停在鎖定畫面並繼續記錄。可行做法：（1）維持現狀；（2）偵測到固定解除時立即再呼叫 `startLockTask()`：手機未上鎖時會再跳確認對話框（「知道了」在右下角），手機已上鎖則沒有作用（G1 平台測試第 5 項）；（3）視同解鎖，結束 FR-45 場次。建議（2），並在狀態列顯示「固定已解除」。這個手勢在殼內是否會被誤觸，要到 G3 泳池才知道；若 G3 不發生，維持現狀即可。
- [ ] FR-93 自訂預設要出現在 FR-12 選擇器且不捲動，但右欄以 64 dp 計最多 5 格，已滿。自訂預設取代某個內建預設，或另行規劃？（M9 前決定）
- [ ] FR-32 對焦滑桿（只在微距出現）的位置：左欄空格加長，或微距時變焦條位置改為對焦滑桿？（M9 前決定）
- [ ] FR-13 影片在直向介面下是直向還是橫向？（M7 前決定）

v0.1 審閱發現的文件內部不一致，每項決定後需回頭修正對應章節：

- [ ] 物種辨識的版本：FR-97 標為 P1（依版本表應在 v1.1），但版本表把「裝置上物種辨識」列在 v2.0。FR-97 降為 P2，或版本表移到 v1.1。
- [x] 潛水電腦對齊的版本：FR-44 標為 P0（v1.0），但版本表把「潛水電腦對齊 UI」列在 v1.1。需寫明 v1.0 是否只做對齊邏輯，以及「手動修正時鐘偏移」屬於哪一版。 → 2026-09-28 決定：FR-44 整項延到 v1.1，改為 P1。
- [ ] LOG 錄影：上方仍問是否需要，但 FR-94 已定為 P1 並有驗收標準。若決定不做，需同時刪除 FR-94。
- [x] 預設檔式：上方仍在 HEIC 與 Ultra HDR JPEG 間選擇，但 FR-61 已寫定 10-bit HEIC；5.1 節捷徑表稱 JPEG\_R 是「FR-61 的兩個實作選項之一」，FR-61 本文卻只有 HEIC；FR-91 驗收標準寫的是「成品 JPEG」。決定後統一三處。 → 已統一：新增 FR-61a，5.1 節捷徑表改指 FR-61a，FR-91 的「成品 JPEG」與 v1.0 一致。
- [x] RAW 保留手勢：上方仍在長按縮圖與專用鍵間選擇，但 FR-62 已寫定「長按預覽縮圖」。→ 已決定沿用 FR-62。
- [x] 快門與邊緣安全區：FR-52 要求快門佔「螢幕短邊整條區域」，FR-55 要求所有可點擊元件距四邊 ≥ 48 dp。需定義「整條」是否指內縮 48 dp 後的寬度。→ 2026-09-28 決定：安全區以 12 mm 為準（原文「約 48 dp」換算有誤，48 dp ≈ 7.6 mm，12 mm ≈ 76 dp），快門條寬度扣除兩側安全區。
- [ ] 連拍與 DNG：FR-68 規定連拍只存 HEIC、不存 DNG，FR-63 規定焦點堆疊自動保留 DNG，而焦點堆疊（FR-33）本身以連拍實作。需寫明焦點堆疊不適用 FR-68，或訂定優先順序。
