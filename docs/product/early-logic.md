# v1.1 提前開工的純邏輯

2026-09-30 · 狀態：草案；程式已寫、JVM 測試通過，尚未接上介面與相機，待維護者確認第 3 節

v1.0 的進度卡在潛水機會，不在開發時間（[roadmap.md](roadmap.md)）。2026-09-30 維護者決定：等待下水期間，先做 v1.1 裡不需要手機就能開發與測試的邏輯。[roadmap.md](roadmap.md) 第 3 節原本的前置條件「v1.0 已發布」，對這些項目改為只約束「接上」與「驗收」。

## 1. 做法

- 只新增檔案與套件，不改 v1.0 已通過 G1 的程式路徑（相機請求、潛水鎖定畫面、寫檔），所以不必重跑 G1。
- 每項都是純邏輯，附 JVM 單元測試；平台相依的部分（感測器、MediaStore、Camera2 鍵）只留介面位置，接上時再寫。
- 門檻與常數凡是沒有實測依據的，程式中標「Proposed」或 `UNVERIFIED(Gx)`，本文第 3 節列出。
- 合併時機由維護者決定；撰寫者建議 v1.0 發布前不合併進 `main`。

## 3. 待維護者確認的解讀與提議

| 項目 | 撰寫者的做法 | 理由 |
| --- | --- | --- |
| FR-57 喚醒的那一下 | 只喚醒，不傳給底下的按鍵（可切換） | 暗畫面上誤按快門的機會高；代價是要多按一次 |
| FR-57「亮度 30%」 | 視窗亮度 0.3，且不高於原本亮度 | M3 實測熱節流時亮度已低到 0.217；v1.1 情境下也會發生是推測，G2 驗證 |
| FR-58「閃光燈已關」 | 解讀為手機手電筒；APP 本身不會觸發閃光燈（FR-81） | 手電筒在殼內會照亮與發熱；也可能是指外接閃燈，那就只能請潛水員自己看 |
| FR-58 電量門檻 | 低於 50% 警告（提議） | NFR-3 允許 90 分鐘用掉 35%，再留 15 個百分點 |
| FR-58 容量門檻 | 少於 1,100 張警告（提議） | NFR-1 場次為 300 張加 10 次各約 80 張的連拍 |
| FR-70 標星的張數 | 標星的一律保留，不算在 N 張內 | 避免一鍵把潛水員已標記的照片送進回收桶 |
| FR-66 刪除去處 | 批次刪除也先進回收桶 | 與 FR-70、FR-73 一致，7 天內可復原 |
| FR-69 門檻 | 清晰度低於堆疊最佳的 50%、暗部剪切 > 50%、亮部剪切 > 5% 判為失敗 | 全部是佔位值，要用 M6 起收集的 20 組連拍校正 |
| FR-22「隨預設切換」 | 每個預設各自記住選用的記憶槽，沒選時用校正表 | 需求原文可解讀為其他意思 |
| FR-22 量測來源 | RAW 區塊，不用預覽畫面 | RAW 是線性的，不受目前增益與色彩矩陣影響（ADR-0002） |
| FR-44 找不到深度的間隔 | 前後兩筆深度相隔超過 60 s 就不內插（提議） | 一般潛水電腦 2–30 s 記錄一筆 |
