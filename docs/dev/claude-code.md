# 與 Claude Code 協作：控制 context 與用量

2026-09-28 · 狀態：已採用

## 1. 原理

Claude Code 的主要成本有兩項：

- **每次啟動都會載入的內容**：根目錄的 `CLAUDE.md`，以及它用 `@` 匯入的所有檔案。
- **工作中讀進來的檔案**：讀進來之後會留在 context 裡，直到 `/clear` 或被壓縮。

所以規則只有兩條：啟動時載入的東西越少越好；每次只讀需要的小檔案。

## 2. 專案的結構安排

| 機制 | 做法 |
| --- | --- |
| 根目錄 `CLAUDE.md` | ≤ 60 行，只放規則與索引位置，不用 `@` 匯入任何文件 |
| 子目錄 `CLAUDE.md` | ≤ 30 行。Claude Code 讀到該目錄的檔案時才載入（推測是按需載入，行為以 Claude Code 官方文件為準） |
| 目錄索引 `README.md` | 先讀索引，決定要讀哪個檔案，再讀檔案 |
| 檔案長度上限 | 單一檔案 ≤ 300 行，讀錯一個檔案的代價有上限 |
| 需求以編號搜尋 | 用 `grep -rn "FR-62 " docs/product/requirements/`，不要整批讀取 |
| `.claude/settings.json` | 禁止讀取建置產物、金鑰、`LICENSE` 全文 |

## 3. 工作習慣

1. **一個 session 做一件事**。換題目前先 `/clear`，不要在同一個 session 裡從相機管線跳到上架文件。
2. **開場給精準的範圍**。例如「做 FR-62 的環形緩衝，相關 ADR 是 0005，模組是 `core/store`」，比「繼續做 RAW」省很多探索成本。
3. **長工作先讓 Claude 列計畫**，確認後再動手，避免讀了一堆檔案才發現方向不對。
4. **大範圍搜尋請 Claude 用子代理**，只把結論帶回主對話，不把搜尋過程留在主 context。
5. **不要把大量輸出貼進對話**。建置 log、測試 log 先存成檔案，請 Claude 用 grep 找需要的部分。
6. **對話變長時**，用 `/compact` 並附上要保留的重點；工作階段告一段落時，把決定寫進文件，而不是依賴對話紀錄。

## 4. 記憶

- 專案的事實一律寫進 repo 的文件，不寫進 Claude Code 的記憶。
- 記憶只放 repo 裡沒有、而且跨 session 需要的東西，例如「repo 是公開的，推送前要先確認」。
- 推測性的內容不寫進記憶；一定要寫的話，標示 `status: unverified` 以及查證方法。
